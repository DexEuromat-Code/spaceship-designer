# Spaceship Designer (for Space Engineers) — Manual Test Suite

Manual acceptance tests written in BDD (Gherkin) style. Each file describes **one feature**;
the structure reads as a specification:

```
Feature
  Background            ← setup shared by every scenario in the file
  Given <precondition>  ← the state of the app before the tester acts
    When <action>       ← what the tester does
      Then <outcome>    ← one checkable expected result (has a test ID)
```

## How to run

1. Use a desktop browser (Chrome or Edge, latest). Open `index.html` **from disk**
   (double-click), not from a preview — automatic saving and the help links need a real file.
2. Run every file from the top. Perform the **Background** first, then for each `Given`
   prepare the state, perform the `When` action, and check each `Then`.
3. Record the result of every `Then` (by its ID) in
   [`Spaceship_Designer_Test_Results.xlsx`](Spaceship_Designer_Test_Results.xlsx):
   choose **PASS** or **FAIL** in the *Result* column and describe any deviation in
   *Tester comment* (what happened, browser, steps to reproduce).
4. Button and label names are quoted exactly as they appear in the app (the UI is in English).

## Test data

| File | Content | Used by |
|---|---|---|
| `examples/basic-colors_palette.json` | Palette with 6 blocks (Red, Orange, Yellow, Green, Blue, Purple) | PFL, TOL, LAY, DIR, CPY |
| [`test-data/test-ship-alpha.json`](test-data/test-ship-alpha.json) | Test ship, constant 9-wide box, direction **Bow → Stern** | PRN (also handy for TOP) |
| [`test-data/test-ship-beta.json`](test-data/test-ship-beta.json) | Test ship, tapered hull 5 → 7 → 9 wide, direction **Stern → Bow** | PRN-09, PRN-10 (also handy for DIR-09) |

Both test ships use the full Standard palette (16 blocks on 2 palette pages) and share this geometry:

- **Length:** layers 1–15 (the project length is 25 — the app's minimum — so layers 16–25 stay empty).
- **Height:** levels 1–6 (bottom 6 rows of the grid). **Width:** up to 9 blocks, centered on column 17 (columns 13–21).
- **Level 1 and level 6:** completely filled with one block type.
- **Levels 2–5:** alternating patterns of single blocks and clusters of 3 or 4 blocks.

| Level | test-ship-alpha.json | test-ship-beta.json |
|---|---|---|
| 6 | #07 Light Armor — full (135 blocks) | #06 Heavy armor — full (115) |
| 5 | #10 ION Thruster — single blocks, checkerboard | #15 BATTERY clusters of 4 + #01 H2 Tank clusters of 4 / singles, every other layer |
| 4 | #03 Conveyors — 2 × 2 clusters of 4 | #13 Pistons — L-shaped clusters of 3 |
| 3 | #01 H2 Tank / #05 O2 Tank — clusters of 3, alternating colors | #12 Door — single blocks on diagonals |
| 2 | #15 BATTERY — single blocks, checkerboard | #05 O2 Tank — lines of 4 blocks along the length |
| 1 | #06 Heavy armor — full (135 blocks) | #07 Light Armor — full (115) |

With *Skip empty levels* ticked, printing either ship gives **6 pages (levels 1–6)**.
The files are generated by [`test-data/build_test_ships.py`](test-data/build_test_ships.py) from
`Standard_palette.json`; rerun it after changing the palette:

```bash
python tests/manual/test-data/build_test_ships.py
```

- Create any other data directly in the app as described in each `Given`.
- Tip: after preparing a complex state (e.g. several saved layers), save it with **Save to JSON**
  and reload it later with **Load JSON** to speed up re-runs.

## Regenerating the results sheet

The spreadsheet is generated from these markdown files, so the IDs always match.
After editing tests, run:

```bash
python tests/manual/build_results_sheet.py
```

> Regenerating overwrites the spreadsheet — copy recorded results elsewhere first.
